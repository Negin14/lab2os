# Частина 3. Трансляція віртуальних адрес

Тема: сторінкова організація пам'яті. Інформація: OSTEP [18. Paging: Introduction](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-paging.pdf), [19. Paging: Faster Translations (TLBs)](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-tlbs.pdf). Варіант: ваш номер за списком, завдання у [variants.md](variants.md).

## Мета

Виконати вручну те, що апаратура робить при кожному зверненні до пам'яті: розбити віртуальну адресу, знайти запис таблиці сторінок, перевірити права, зібрати фізичну адресу.

## Що дано у варіанті

- Розрядність віртуальної адреси (наприклад, 15 біт) і розмір сторінки (наприклад, 4096 байт).
- Кількість page frames фізичної пам'яті.
- Таблиця сторінок: для кожної сторінки біт valid, номер frame і права `rwx`.
- Шість звернень: віртуальна адреса й операція (читання, запис, виконання).

## Алгоритм

1. Біти зміщення: `log2(розмір сторінки)`. Для 4096 байт це 12.
2. Біти номера сторінки: розрядність адреси мінус біти зміщення. Кількість записів у таблиці: `2^(біти номера сторінки)`.
3. Для адреси: номер сторінки — старші біти, зміщення — молодші. У шістнадцятковому записі при 12 бітах зміщення це просто три останні цифри.
4. Запис таблиці з цим номером: якщо `valid = 0` — page fault, сторінки немає в пам'яті, ОС має її завантажити (або вбити процес, якщо адреса не належить жодній області).
5. Якщо `valid = 1`, перевірити права: запис потребує `w`, виконання — `x`, читання дозволене завжди. Порушення — protection fault (segfault для процесу).
6. Інакше фізична адреса: `frame × розмір сторінки + зміщення`. Розрядність фізичної адреси: `log2(кількість frames) + біти зміщення`.

### Розв'язок

Біти зміщення: 8, біти номера сторінки: 4, записів у таблиці: 16, розрядність фізичної адреси: 14 біт, розмір таблиці при 2-байтовому записі: 32 байти.

| №   | VA    | Операція  | Сторінка | Зміщення | Результат                                          |
| --- | ----- | --------- | -------- | -------- | -------------------------------------------------- |
| 1   | 0xA83 | виконання | 10       | 0x83     | protection fault: виконання заборонено правами rw- |
| 2   | 0x537 | читання   | 5        | 0x37     | PA = 0x1F37                                        |
| 3   | 0xE2F | виконання | 14       | 0x2F     | PA = 0x332F                                        |
| 4   | 0x86F | читання   | 8        | 0x6F     | PA = 0x2A6F                                        |
| 5   | 0x008 | запис     | 0        | 0x8      | page fault: сторінка не завантажена (valid = 0)    |
| 6   | 0x152 | запис     | 1        | 0x52     | PA = 0x1E52                                        |

Хід для звернення 2 (0x537, читання). Сторінка 256 байт, отже зміщення займає 8 біт, тобто дві молодші шістнадцяткові цифри: 0x37. Номер сторінки — решта: 0x5 = 5. Запис 5 таблиці: valid = 1, frame 31, права r-x. Читання дозволене завжди. Фізична адреса: 31 × 256 + 0x37 = 0x1F00 + 0x37 = 0x1F37.

Хід для звернення 1 (0xA83, виконання). Зміщення 0x83, сторінка 0xA = 10. Запис 10: valid = 1, права rw-, біта x немає. Виконання заборонене: protection fault, процес отримає SIGSEGV.

## Запитання для самоперевірки й захисту

- Скільки пам'яті зайняла б таблиця сторінок для 48-бітної віртуальної адреси при 4-КіБ сторінках і 8-байтових записах, якби вона була одним масивом? Як це вирішують реально?
- А скільки зайняла б така таблиця при сторінках 2 МіБ?
- Що робить TLB і чому без нього кожне звернення до пам'яті було б у кілька разів повільнішим?
- Чому page fault і protection fault ядро обробляє по-різному, хоча обидва — винятки від процесора?
